4. Kernel Changes
4.1 Fault Handling → Incidents (recursive correction begins here)
In a single address space, "recover from a ring-0 fault" is possible because Halo tasks own arenas and everything has destructors. The fault handler unwinds the task, not the machine.

// Sys/Kernel/Arch/x86_64/Fault.halo
@pinned @core
fn fault_entry(frame: Ptr[TrapFrame]) -> U0 {
    unsafe {
        let task = Cpu.current_task();
        let sym  = Symbols.lookup_pc(frame.rip);

        if (sym.is_core || task.is_core) {
            // Core fault: we cannot trust this kernel instance any more.
            Pstore.write(CrashRecord(frame, sym, task, Telemetry.tail(4096)));
            Slot.mark_crash();                 // increments crash_budget counter in bootloader vars
            Arch.reboot_into(Slot.current, arg = "--resume-incident");
        }

        // Non-core fault: quarantine the symbol, unwind the task, file an incident.
        HotPatch.quarantine(sym);              // future callers get `throw 'Quarantnd'` instead of UB
        let inc = Incident(
            kind      = .HardwareFault,
            code      = frame.vector_code(),
            symbol    = sym,
            backtrace = Unwind.capture(frame),
            arena     = task.arena.snapshot_meta(),
            context   = Telemetry.tail(512),
        );
        Gardener.incidents.push(inc, priority = .High);
        Sched.unwind_and_kill(task);           // runs destructors, frees arena, never returns
    }
}
Halo-level exceptions (throw) that escape a task's top frame take the same path via Task.uncaught_handler. Driver watchdog timeouts, failed @tests, failed @invariants, and telemetry anomalies (latency SLO breach, memory leak slope) are synthesized into Incidents by Sys/Kernel/Gardener/Sensors.halo.
